# ДнД: общие ходы, личная инициатива и прогресс

База проверки: `origin/main` на `42178f6`, после PR #736. Локальная ветка
синхронизирована fast-forward. Источник наблюдений — предоставленный пользователем
лог за 22 сентября, 22:03–23:04; художественных ответов бота в этом фрагменте нет.

## Что видно в логах

- Повторяется сбор заявок от четырёх участников (`submitted=0..4 expected=4`).
  После генерации снова начинается сбор всей партии. Логи подтверждают повторение
  общих окон, но не позволяют оценить содержание каждого художественного ответа.
- `applying_result_without_snapshot` повторяется до 23:02:19. PR #736 уже исправляет
  потерю ссылки на snapshot при нормализации состояния. После перезапуска в 23:02
  следующий показанный результат в 23:04 этой ошибки не содержит; этого недостаточно
  для вывода об отсутствии ошибки во всех последующих ходах.
- Gemini возвращал 503 и 429, после чего срабатывал переход на flash-lite.
  Успешная генерация сама по себе не гарантирует продвижения истории.
- Контекст сокращается со 150 тысяч символов примерно до 18 тысяч. Следовательно,
  важен состав отправляемой памяти, а не только полнота сохранённой истории.

## Оставшиеся причины в коде

1. Memory v2 сохраняла лишь последние 300 символов старого контекста. Подсказка
   `СЛЕДУЮЩИЙ ФОКУС` находилась перед более поздними правилами и терялась.
2. Стиль задавал максимум 70 слов и обрезал результат, хотя групповой запрос для
   четырёх заявок уже разрешал 197 слов. Коррекция дополнительно возвращала малый
   лимит. Это могло удалять последствия поздних заявок.
3. Проверка третьего общего INPUT просила коррекцию, но разрешала после неё ещё
   один общий INPUT. Очередь распределяла уже выбранные личные ходы, не обеспечивая
   их появление. При разрешении групповых заявок она также пропускала новый личный INPUT.
4. Извлечение исходных заявок не учитывало новый разделитель `Сначала РАЗРЕШИ`;
   инструкции об осмотре ошибочно попадали в текст действий игроков.
5. Прокси отправки автоматически приписывал случайную стандартную колкость к
   сообщениям, включая служебные приглашения к ходу.

## Изменения

- Очередь личной инициативы включена отдельным ранним блоком ограниченной памяти.
- После двух общих продолжений следующий свободный выбор адресуется герою очереди.
  Сначала модель получает коррекцию; если она снова возвращает общий INPUT,
  технический тег адресуется одному герою. Содержание последствий сохраняется.
  Явные адресаты, броски по заявкам, атаки и завершение истории не переназначаются.
- Новый личный INPUT расходует очередь даже в продолжении группового хода.
- Групповой лимит текста учитывается при генерации, обрезке и коррекции.
- Удалены повторяющаяся подсказка про «дальше» в обычном приглашении к ходу и
  автоматические дежурные колкости. Сама команда и сообщения восстановления доступны.
